# Rider personalities: production integration audit

## Scope and baseline

The existing personality work was recovered from the clean local branch
`codex/rider-personalities-local`, source HEAD `f4fd587b`. Its four commits were
integrated onto application baseline `7da03ab0`, preserving the developments
delivered since their common ancestor `12c49ee2`.

The feature assigns one deterministic personality from a catalog of 25 to each
scouting candidate, academy rider and professional rider. Academy recruitment and
professional promotion preserve the personality. Existing players, contracts,
ratings and completed classifications are not regenerated by this integration.

## Compatibility review

- The road engine keeps the existing hard-stage attrition calculation, stamina
  factors, working costs and leader-protection reductions. Franc-tireur changes
  only a limited solo effort; recovery and relay personalities use the existing
  support, pursuit and energy paths, including their costs and eligibility rules.
- Explicit preparation remains authoritative: protected leaders, forbidden
  breakaways, designated duties and planned attackers remain excluded from
  incompatible spontaneous actions. A willing Solidaire can change the selected
  eligible helper, while the existing escort limit and designated-helper priority
  remain in force.
- Road personalities do not affect individual time trials. Régulier changes the
  energy cost of an actual team time-trial relay, with shelter and relay-share
  checks preserved. Imprévisible applies on the selected final road stage and
  uses its own deterministic roll.
- Junior personality scoring composes with the latest club and federation
  tactical scorer. Final settlement preserves published stage records; tours
  already started retain their former personality scoring for the remaining
  stages. The merge retained both the tactical and personality SQL suites.
- Each of the four scoring anchors in migration `20261117102000` occurs exactly
  once in the production function definitions captured for this audit. The
  migration therefore patches the actual scoring paths rather than replacing
  the tactical engines wholesale.
- The existing low-morale renewal refusal remains in its renewal entry points.
  Fidèle reacts after a successful contract write and does not bypass that
  refusal, salary calculation or deferred-transfer activation.
- Assidu multiplies training gains within the current settlement functions; it
  does not restore the removed seasonal progression cap. Morale effects use the
  existing persistent, deduplicated event ledgers.
- Historical official snapshots remain authoritative. New result-leadership
  effects require frozen evidence of the actual DS appointment, avoiding an
  automatic leader designation being interpreted as the manager's decision.

## Database and runtime cost

Migration `20261117102000` now runs inside a transaction with a 2-second lock wait
and 20-second per-statement timeout. It adds the partial index used to look up a
junior's stage participation history. Junior morale checks run only for a real
Globe-trotteur result and use the existing morale lock and unique ledger key.

Personality fields extend existing batched application reads. The simulation
keeps an in-memory event map deduplicated by rider and effect; it does not make
network requests per rider or per simulation tick. Follow/relay candidate scans
use the existing bounded peloton. Weather is resolved once for a road stage.

An isolated local timing comparison used 140 riders on each of four profiles,
three warmups and 15 alternating measured runs for the baseline engine, the new
engine without personalities, and the new engine with a mixed catalog. Medians
in milliseconds:

| Profile | Baseline | New, neutral | New, mixed personalities |
| --- | ---: | ---: | ---: |
| Sprint | 167.90 | 169.85 | 172.26 |
| Hilly | 261.46 | 269.51 | 271.18 |
| Mountain | 188.49 | 189.60 | 186.12 |
| Cobbles | 325.17 | 319.53 | 320.88 |

Other tests ran concurrently, so these numbers are indicative local measurements,
not a production SLA. They show no material runtime increase in this sample.
For all four neutral scenarios, full sporting results and the entire timeline
were identical to the baseline engine.

## SQL delivery verification

The other nine migrations also use explicit transactions with bounded lock and
statement waits: 500 ms and 10 seconds, except preparation exposure, which keeps
its 5-second statement limit. Result, Force tranquille and mixed-zone patches
normalize their multiline anchors to the newlines returned by PostgreSQL. This
fixes a reproducible failure when SQL files are checked out with Windows CRLF.
Unexpected function bodies still abort the complete migration transaction.

The seven modified production function definitions were captured read-only by
the delivery owner and loaded into an isolated PGlite database. All exact
replacement anchors passed. Production preparation return types have the same
36 existing fields, in the same order. The mixed-zone column grant retains all
16 readable public fields and hides only the saved internal event context.

The new lifecycle fixture loads 3,168 professionals, 2,925 scouting candidates
and 1,395 academy records. Its isolated personality backfill completed in 207 ms;
this is a fixture measurement, not a production timing guarantee. It checks
candidate-to-academy-to-professional identity continuity and the existing
unqualified academy homegrown trigger. Updating the new field neither grants
homegrown bonuses nor creates historical morale events. New identities preserve
their personality through recruitment and promotion.

Sociable runs in the existing maintenance path, using its advisory lock, at most
250 events per batch and existing unique morale event keys. The fixture checks
batch continuation and a zero-event third run. The first maintenance run may
award the new one-time integration benefit to existing Sociable riders; later
historical results, training sessions and contracts are not replayed.
